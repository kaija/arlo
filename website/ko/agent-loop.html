에이전트 루프

모든 요청은 같은 경로를 따릅니다. 컨텍스트를 준비하고, 작업에 대해 추론한 뒤, 일이 끝날 때까지 도구 호출을 반복합니다. TUI든 원샷 CLI든 라이브러리든, 모든 Arlo 실행의 바탕이 되는 핵심 처리 로직입니다.

트리거

턴은 사용자 프롬프트, 예약된 작업, 이벤트나 웹훅, 알림, MCP 요청에서 시작됩니다. 어디서 왔든 같은 파이프라인으로 들어가며, 별도의 우회 경로는 없습니다.

요청마다
  1. 프롬프트 — 어떤 트리거에서 왔든 들어온 요청을 동일한 형태로 정규화합니다.
  2. 컨텍스트 준비 — 히스토리, 파일, 도구 스키마를 가져와 조립하고 압축해 컨텍스트 윈도우에 맞춥니다.
  3. 모델 추론 — 무언가에 손대기 전에, 모델이 작업을 이해하고 접근 방식을 계획합니다.
Agentic 루프
  1. 다음 행동 계획 — 바로 다음 한 단계를 결정합니다.
  2. 도구 선택 — 그 단계에 가장 알맞은 도구를 고릅니다.
  3. 권한 확인 — Human-in-the-Loop 관문. 거부된 호출은 실행되지 않습니다.
  4. 도구 실행 — 실제로 작업을 수행합니다.
  5. 결과 관찰 — 실패를 포함해 출력과 피드백을 수집합니다.
  6. 메모리 갱신 — 결과를 컨텍스트와 세션 상태에 반영합니다.
  7. 작업 평가 — 더 할 일이 남았나? 남았다면 계획으로 돌아가고, 아니면 루프를 빠져나옵니다.
완료
  1. 최종 응답 — 답변을 생성하고 요약해 전달합니다.
  2. 후처리 — 로그, 감사 기록, 텔레메트리.
  3. 세션 종료 — 상태가 저장되므로, 이후의 트리거가 같은 세션을 이어갈 수 있습니다.

각 단계는 이벤트로 스트리밍됩니다. TUI가 실시간으로 그리는 것도, Arlo를 임베드한 애플리케이션이 구독할 수 있는 것도 바로 이 이벤트입니다. 구조 살펴보기 →
